1. System Overview & Hardware Fleet

ReWatch IoT is a zero-cloud, multi-tiered physical cybersecurity appliance engineered for residential and commercial building automation environments. It continuously observes the local IoT subnet, detects malicious probing and physical actuator anomalies, evaluates systemic threat mathematically, visually mirrors fleet health onto physical hardware twins, and executes automated deterministic containment playbooks when unacknowledged incidents cross critical thresholds.

Three Raspberry Pis and two ESP32 microcontrollers form an air-gapped security fabric inside a tamper-resistant enclosure:

3. Passive Sniffing & Anomaly Detection

The detection pipeline splits into two continuous real-time subsystems:

3.1 Passive Network Sniffer (Sentinel)

Utilizing raw packet capture, Sentinel inspects Layer 2 frames and Layer 3/4 headers without assigning itself an active IP on untrusted segments:

  • ARP Sweep Detection: Tracks unique target IP lookups per source MAC in rolling 10-second windows. Exceeding 12 unique IP queries generates an arpsweep impulse (35 pts).
  • Ping / ICMP Echo Sweeps: Sliding window rate-limiter catching echo requests targeting multiple subnet hosts (30 pts).
  • TCP SYN / Stealth Scans: Analyzes half-open TCP handshakes (SYN without ACK, FIN/NULL/XMAS scans). Scans across ≥8 ports within 4 seconds trigger a portscan impulse (45 pts).
  • Packet Flood Detection: Ingress packet-per-second monitoring across broadcast and unicast channels. Exceeding 450 PPS triggers a flood impulse (75 pts).
  • New Device Onboarding: Compares observed MAC addresses and DHCP discoveries against the authorized cryptographic device profile registry (20 pts).

3.2 Physical Actuator & Telemetry Anomaly Engine

Sentinel's AnomalyDetector evaluates honest device telemetry across continuous kinematic limits:

  • Temperature Rate-of-Change (ΔT/Δt): A rate of ±0.5 °C/s or higher indicates artificial heating, Peltier tampering, or sensor injection (warn level, 45 pts).
  • Setpoint Drift Limit: When ambient temperature deviates from commanded setpoint by ≥4.0 °C for more than 15 seconds, a drift anomaly opens (warn level, 45 pts).
  • Critical Temperature Excursion: Sustained readings ≥32.0 °C or ≤10.0 °C open a critical threat condition immediately (90 pts).
  • Power Spike Overload: Smart plugs exceeding configured wattages (e.g. 2,000 W baseline, 3,100 W surge) trigger overload containment.
  • Forced Physical Breaches: Magnetic reed switch triggers without authorized WebAuthn badge unlock open forced-entry alarms.

4. Dual-Path Verification Architecture

A central tenet of ReWatch is that an attacker who has compromised an IoT device's firmware can falsify its MQTT telemetry. To counter this, ReWatch implements dual-path out-of-band verification:

Dual-Path Invariant: For every enrolled device, telemetry published over MQTT is independently corroborated by the Pi 4 Core querying the device's secondary HTTP/REST telemetry diagnostic socket over an orthogonal network path.

If the MQTT topic reports 20.0 °C but the direct Wi-Fi probe returns 34.5 °C, or if the device fails to respond within 2.0 seconds, a telemetry mismatch impulse (40 pts) fires. The system flags the device as compromised / integrity alert rather than relying on unauthenticated self-reporting.

5. Mathematical Threat Scoring Model

Threat is modeled not as discrete binary alerts, but as a single continuously undulating scalar score between 0 and 100.

score(t) = clamp( maxc ∈ Conditions(Pc) + ∑i ∈ Impulses [ Pi · 2-(t - ti) / τ ] , 0 , 100 )

Where:

  • Conditions (Pc): State-based continuous threat indicators. As long as a condition persists (e.g., an AC unit actively sitting at 35 °C), its points remain pinned at full weight. The moment the condition normalizes, its points drop instantly.
  • Impulses (Pi): Ephemeral event-based indicators (e.g., a SYN flood or an Nmap scan). Each impulse has an initial point payload that decays exponentially over a half-life of τ = 60.0 seconds.

This smoothly binds baseline activity between 5.0 and 19.8, proving that the monitoring engine and visual twin are dynamic and responsive without triggering false threat warnings.

Anti-Chatter Hysteresis

To prevent rapid strobe transitions near band boundaries (e.g., hovering around score 30), a strict hysteresis filter is enforced on downward transitions: the score must drop at least 3.0 points below threshold and maintain that level for ≥3.0 consecutive seconds before the band drops back to GREEN.

7. The Incident State Machine & Deadlines

When the scalar score reaches ≥70 points, an Incident is formally opened with a cryptographically unique identifier (e.g. inc-171802-68e652). The incident state machine progresses through defined transitions:

  • Operator Acknowledgment (ACK): Clicking "Acknowledge" on the dashboard or clicking the signed token link in the operator's e-mail cancels the automated response. The operator takes responsibility.
  • Automated Containment (PURPLE): If no operator ACK is received within the deadline (120 s in production, 20 s in demo simulation), the band transitions to PURPLE and the automated containment playbook is fired.
  • Clean Resolution to GREEN: When the actuator setpoint is restored and physical telemetry normalizes (score < 30), the purple hold period concludes (6 s), the incident is marked resolved, and the band cleanly transitions back to GREEN.

10. Pi 3 Herald: Air-Gapped E-mail Alerts

Pi 3 Herald handles outbound alerts across an independent uplink. To prevent attackers from blinding the operator by severing the main building gateway, Herald can be provisioned with a secondary cellular or Wi-Fi uplink interface (SMTP_IFACE=wlan0).

Accepted ≠ Delivery Rule: Successful SMTP transmission means the upstream relay accepted the message envelope. It is not cryptographic proof of inbox arrival. Herald explicitly logs transactions as accepted by relay rather than falsely asserting recipient reading.

Herald dispatches alerts for: RED incident opening (with one-click ACK link), operator acknowledgment receipt, PURPLE automation execution, incident resolution, and periodic 5-minute evidence summaries containing rolling event metrics.

11. Forensic Audit Logging & USB Checksums

To resist forensic tampering and storage wear, logging is decoupled across two media:

  • Sentinel USB Stick (WORM Storage): Every bus message is written sequentially to a dedicated high-endurance USB flash drive mounted at /mnt/rewatch-log. Daily directories contain telemetry.jsonl, events.jsonl, and bus.jsonl. Each record contains timestamp, HMAC framing checksum, topic, and payload.
  • SD Card Failover: If the USB drive is unplugged or fails, Sentinel alerts the operator via the fleet panel (usb missing) and safely diverts logs to the local MicroSD card.
  • Rolling SQLite Cache (Pi 4): Pi 4 Core maintains a rolling 5-hour ring buffer in SQLite, enabling sub-millisecond querying for the dashboard history canvas and instant markdown report export.

12. WebAuthn Passkeys & Security Boundary

The operator dashboard is locked behind zero-cloud FIDO2 / WebAuthn passkey authentication:

  • Cryptographic Authentication: Utilizes public-key cryptography (ES256 / RS256). Private keys never leave the operator's hardware security module (YubiKey, Apple Touch ID / Face ID, Windows Hello).
  • Local Challenge Verification: Challenges are generated randomly on the Pi 4 Core using secrets.token_bytes(32) and validated against enrolled public keys stored in SQLite.
  • Session Protection: Successful WebAuthn ceremony issues an encrypted HttpOnly, SameSite=Strict session cookie. No shared passwords or static API keys are ever stored on disk.
  • Emergency Access Code: For initial onboarding or headless kiosk access, start.sh issues ephemeral single-use registration tokens.

15. Operator Runbooks & Troubleshooting

Runbook A: Triaging a RED Incident

  1. Check the Root Cause: Inspect Section 02 (Alerts) to determine if threat is physical (HVAC runaway, forced entry) or network-based (SYN flood, port scan).
  2. Decide Acknowledgment: If you are actively investigating and do not want automated actuator commands fired, press Acknowledge before the countdown timer expires.
  3. Trigger Immediate Response: If containment must run immediately without waiting for the countdown, press Respond now.
  4. Verify Normalization: Once the physical condition is safe (temperature drops below 24 °C, flood ceases), observe the incident resolve cleanly back to GREEN.

Runbook B: Resolving a BLUE Band (Fleet Node Offline)

  1. The band enters BLUE when Sentinel, Herald, or Core stops reporting heartbeats for ≥15 seconds.
  2. Inspect Section 03 (BlackBox) to identify which board is flagged as down.
  3. Check physical Ethernet cabling and power supply to the affected Raspberry Pi.
  4. Verify Mosquitto service status: sudo systemctl status mosquitto on Pi 4 Core.
  5. Once the node resumes publishing heartbeats, the band clears automatically to GREEN.

Runbook C: Emergency Master Reset

To instantly clear active test drills, reset threat score to baseline, restore GREEN band, clear UI incident cards, and restart scene state, press:

Ctrl + Shift + R (Windows / Linux)  |  Cmd + Shift + R (macOS)

This commands a server-side scenario reset: setpoints return to 20 °C, any active incident is marked resolved, and the threat engine re-anchors to calm baseline.
